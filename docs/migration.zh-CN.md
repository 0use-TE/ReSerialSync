# 从 SerialSync 到 ReSerialSync：一次由 AI 辅助完成的 Avalonia 重写

我想把自己做过的串口工具，变成一个可以长期使用、继续扩展的工作台。
旧版 [SerialSync](https://github.com/0use-TE/SerialSync) 使用 .NET MAUI Blazor Hybrid、MudBlazor 和 NLog，
仓库创建于 2025 年 3 月 20 日。这次我用 Avalonia 12 和 .NET 10 重写了它，并命名为 ReSerialSync。

这是已有应用的重写。原始 UI 是 Razor、CSS 和 WebView，新的 UI 是 AXAML、样式和视图模型。
我没有把旧界面原封不动搬过来，而是重新考虑了多串口、工作区布局和设备调试的使用流程。
Blazor Hybrid 本身不是古老技术；这里的价值是更换桌面 UI 实现和完善实际工具。

## 从界面迁移到工作流程重构

新版把串口列表、当前配置、接收、发送、日志和 AI 对话放入可调整的 Dock 工作区。
串口列表和配置分开后，设备数量增加也不会把所有参数挤在同一处。
点击设备只切换当前上下文，其他已连接串口继续运行。
每个串口分别持有连接、增量解码器、收发缓冲、计数和定时发送状态。

布局、配置、主题、语言及发送内容自动保存。通过 System.Reactive 和扩展方法观察变化，
防抖后写入配置文件，退出时再刷新一次。启动后恢复工作区，但不会自动连接或启动定时发送。
这使恢复布局和真正操作设备之间有清晰的界限。

颜色使用 Semi.Avalonia 和 GOZA.Dock 的现有主题资源；明暗模式不靠手写一套固定背景色切换。
中英文资源会更新已经显示的控件、选项和通知。Material Icons 让顶部操作更紧凑，
设置页统一提供样式、AI 配置、教程和作者信息。精简模式隐藏日志与 AI 区域，恢复时保留完整布局。

Crystal.Avalonia、GOZA.Dock 和 DotKernel 也是我持续开发的库。
这次重写让它们面对真实应用中的生命周期、状态恢复、AOT 和跨平台问题。
依赖版本见仓库的中央包管理文件，第三方组件保留各自许可证。

AI 助手能够读取当前串口场景，刷新和选择设备、配置参数、连接或断开指定串口，
也能把待发送内容填写到编辑器。发送字节和启动定时发送仍由用户操作。
模型地址、名称和 API key 在设置中填写，普通串口功能不需要 AI 服务。
按本项目的跨平台设计选择，key 明文保存在本地配置中；演示和发布包不包含个人配置或凭据。

## AI 如何参与开发

重写从 2026 年 10 月 1 日持续到 10 月 8 日。按我的回顾估算，累计主动投入约 8 小时；
没有逐分钟计时，这不是经过基准测量的效率结论。
代码主要交由 AI 编写，我负责提出需求、观察界面、连接真实硬件、反馈问题并决定取舍。
库的既有开发投入不计入这次约 8 小时的重写估算。

实际过程是不断迭代：从不够方便的串口选择改成独立列表与配置区；
从拥挤的文字按钮改为图标；再调整间距、主题、设置和对话空态。
结构清晰的 AXAML、绑定和视图模型给 AI 提供了可定位的修改位置，
自动化检查和截图又让修改结果可以被检验。
顺畅并不意味着一次生成就正确，下面的问题都需要继续定位和修复。

## 真正花时间的问题

**事件绑定与 Native AOT。** 原来的事件名查找依赖反射，在 AOT 后启动扫描未按预期执行。
Crystal.Avalonia 改为使用 Avalonia 路由事件注册表，并支持显式 RoutedEvent。
修复放在库里，应用不再靠 DynamicDependency 保留字段。
普通 CLR 事件的反射兼容分支仍有运行时范围限制，不把它描述为所有事件都支持 AOT。

**Linux 依赖兼容。** 最初直接引用 Tmds.DBus.Protocol 0.95.1，
但 Avalonia 12.0.0 的 Linux 后端仍需要已被新版本删除的 Connection 类型。
编译成功不代表启动成功；最终选择保留旧 API 的 0.92.0。

**发布后还需要系统环境。** Linux 启动遇到缺少 libICE.so.6，
说明 SelfContained 并不会把所有系统图形库都一起提供。
中文显示需要安装相应字体；WSL 接 USB 串口还需要 usbipd，打开设备需要 Linux 的读写权限。
设备枚举成功与能够打开设备也是两回事。

**串口读块不等于协议消息。** UTF-8 字符、CRLF 都可能跨两次读取。
接收区曾把设备已有的换行再追加一次，出现空行；修复保留原始行尾，
并检查分包 CRLF、不完整 UTF-8 和设备主动发送的空行。

## 验证与交付范围

2026 年 10 月 8 日重新运行的控制台验证完成 122 项检查，
覆盖多串口、拔插、绑定、HEX、UTF-8 分包、主题、本地化、AI 工具调用和自动保存。
测试使用模拟串口、模拟 AI 服务以及 Avalonia Headless，不能替代真实驱动和外部模型验证。
仓库另附 ESP32 自动回复固件，用 PING / PONG 等命令复现收发过程。

Windows x64 与 Linux x64 已有 Native AOT 产物。Windows 有开发过程中的设备收发截图；
Linux 已在 WSL 2 / WSLg 启动，设备访问还经历了权限排查。
目前保留的 Linux 截图记录了该问题，不将其当作 Linux 收发成功证据。
原生 Linux 与 macOS 的实机通信尚未验证，移动端和浏览器仅保留项目入口。
各平台运行方法见[发布说明](releases.md)。

我希望这次升级能给其他开发者一个可以读代码、下载运行并接上设备复现的例子。
后续还需要补齐更多平台的实机验证，再基于实际使用继续改进。
